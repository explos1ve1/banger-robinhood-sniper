# BANGER — запуск українською

Це консольний бот для PONS V2 та пулів Uniswap V3 з WETH у Robinhood Chain.
Він шукає нові запуски, перевіряє ліквідність, комісії та котирування,
а в режимі `live` може купувати й продавати токени за заданими умовами.

## 1. Подивитися термінал без гаманця

Встанови Node.js 22 або новіший, розпакуй проєкт і відкрий його папку в
терміналі. На Windows можна відкрити PowerShell у цій папці.

```powershell
npm ci
npm run demo
```

Це офлайн-демо інтерфейсу. Воно не підключається до мережі та не торгує.

## 2. Увімкнути спостереження за мережею

Створи локальний файл налаштувань. На Windows:

```powershell
Copy-Item .env.example .env
```

На Linux/macOS: `cp .env.example .env`.

Відкрий `.env` у редакторі. Перевір `RPC_URL`, адреси контрактів і залиш
`MODE=watch`. Потім:

```powershell
npm run doctor
npm start
```

Якщо `doctor` пише про таймаут, потрібен робочий RPC Robinhood Chain.
Якщо пише про невідповідність контрактів, перевір адреси за першоджерелами
з [NETWORKS.md](NETWORKS.md). Не вимикай перевірки, щоб замаскувати помилку.

## Додати PONS до наявної установки

Онови файли проєкту зі збереженням папок і виконай `npm ci`.
Свій локальний `.env` та папку `data` залиш: там налаштування і стан позицій.
У `.env` додай:

```dotenv
VENUES=both
```

Це ввімкне PONS V2 разом із попереднім V3-сканером. `VENUES=pons` залишає
лише нові запуски PONS V2. Новий `.env.example` вже містить `VENUES=both`.
Потім виконай `npm run doctor` і `npm start -- --mode paper`.

Бот чекає, поки стартовий податок PONS зникне, обмежує комісії та показує
прогрес кривої в терміналі. Якщо токен переходить у V4, позиція зберігається,
а після появи пулу бот намагається продати її за ETH. Підтримуються PONS-пари
саме з нативним ETH. Деталі — у [PONS.md](PONS.md).

## 3. Спробувати paper-режим

```powershell
npm start -- --mode paper
```

Він читає справжні котирування, але записує умовні покупки. Гроші не
витрачаються; газ у paper-PNL не враховується. Ці результати не доводять,
що реальна торгівля дасть такий самий прибуток.

## 4. Реальні угоди

Режим `live` витрачає справжній ETH. У локальному `.env` потрібно задати
`MODE=live`, `PRIVATE_KEY` окремого гаманця та
`LIVE_ACK=I_ACCEPT_REAL_TRADES`. Ключ нікому не надсилай і не завантажуй
у GitHub. Сід-фразу бот не використовує.

Початкові ліміти: покупка `0.001 ETH`, загальний бюджет входів `0.01 ETH`,
до трьох відкритих позицій. Їх можна змінити в `.env`. Спочатку знову
виконай `npm run doctor`, потім `npm start`.

Клавіші: `p` — пауза нових покупок, `r` — продовжити, `q` — завершити
процес. Пауза залишає контроль відкритих позицій; вихід із програми
зупиняє його. Програма не продає все автоматично під час закриття.

## Що перевірено

Купівлю, продаж, отримання ETH, роботу двох роутерів і відновлення після
обриву RPC перевіряють тести з контрактами Uniswap у локальній EVM.
Реальні кошти в Robinhood Chain під час розробки не використовувалися.
PONS V2: локально перевіряються купівля/продаж на кривій, повернення решти
ETH при частковому виконанні, перехід у V4, точні дозволи Permit2 і вихід
за нативний ETH. Це не перевірка реальних угод у mainnet.

## Як завантажити в GitHub

Для твого репозиторію `explos1ve1/banger-robinhood-sniper`:

1. Розпакуй архів оновлення.
2. На GitHub відкрий **Add file → Upload files** у корені репозиторію.
3. Завантаж вміст архіву, зберігаючи папки `src`, `test`, `docs` та інші.
4. Натисни **Commit changes**. Нові версії файлів замінять попередні.

Видаляти банер, README чи папки вручну не потрібно. Не завантажуй
`node_modules`, `data`, `.env` або файли гаманця. `.env.example` — це
публічний шаблон, його можна завантажувати.

Через Git у наявному клоні після копіювання оновлення:

```powershell
git add src test docs licenses .github package.json package-lock.json .env.example README.md SECURITY.md THIRD_PARTY_NOTICES.md
git commit -m "Add PONS V2 curve trading and V4 exits"
git push
```
